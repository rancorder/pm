# External Watch Log（外部知見の継続ウォッチ台帳）

> **このファイルの位置づけ**
> Qiita/Zenn/技術ブログ/公式ドキュメント等から拾った「OSに効きそうな外部知見」を、
> 検証ステータス付きで管理する受け皿。
>
> **重要（凍結ルールとの関係）**：ここに載る情報は原則すべて **未検証** である。
> 外部記事は「読んだ＝OSに採用」ではない。実案件・実データで当ててから、
> 効いた差分だけを該当モジュール（cards / domain / library / starters）へ昇格させる。
> このファイルは"検証待ちの入口"であり、"確定した知見の置き場"ではない。

## 検証ステータスの定義

| ステータス | 意味 |
|---|---|
| `未検証` | 拾っただけ。まだ実案件で当てていない |
| `検証予定` | 次の実案件（主に8月〜）で試すと決めたもの |
| `採用` | 検証して効いた。該当モジュールへ昇格済み（昇格先を明記） |
| `棄却` | 検証したが効かなかった（理由を残す。同じ轍を踏まないため） |

## 昇格のルール
1. 未検証 → 検証予定：実案件で試す価値があると判断したとき
2. 検証予定 → 採用/棄却：実データで当てた結果で決める
3. 採用時は、該当カード/ドメイン/ライブラリに反映し、ここには「採用済み・昇格先」を残す
4. 記事URLは鮮度が落ちる前提。最終確認日を持たせる

## 使い方（Claudeへ）
- 新しい記事を拾ったら、該当セクションに1行追加。ステータスは原則`未検証`で入れる
- 実案件で当てたら`採用`/`棄却`に更新し、採用なら昇格先モジュールを明記
- このファイルが肥大化したら、`採用`済みは各モジュールへ移し、ここからは削除して索引だけ残す
