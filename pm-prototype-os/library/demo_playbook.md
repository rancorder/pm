# Demo Playbook

プロトタイプを顧客に見せる際の進行台本。デモの成否は成果物の出来ではなく、見せる順序と発話で決まる。

## 原則

1. **顧客のデータで始める。** サンプルIFCで開始しない。可能なら事前に顧客の実ファイル（L2/匿名化済み）を1つ預かり、それを最初にドロップする。「自分のデータが動く」瞬間が価値検証のすべて
2. **機能を説明しない。業務を再現する。**「ここを押すと属性が出ます」ではなく「昨日の定例で出た『この壁の仕様どこだっけ』を、この画面でやってみます」
3. **できないことを先に言う。** 「大容量ファイルは今日は動きません」「精度検証はまだです」を自分から言う。後で露呈するより、先に言えば技術理解の証明になる
4. **デモ後の質問は要件。** デモ中の「これ〇〇はできるの？」をすべて記録し、そのまま `02_need_to_requirement.md` の入力にする

## 進行テンプレ（15分）

| 分 | やること |
|---|---|
| 0-2 | 前回ヒアリングの課題を1文で復唱（「〇〇に時間がかかる、が課題でした」） |
| 2-5 | 顧客データで実演（操作は顧客にやってもらうのが理想） |
| 5-8 | できないこと・次段階の明示 |
| 8-13 | 質問タイム（全部メモ。答えられないものは持ち帰り宣言） |
| 13-15 | 次アクション合意（誰が・何を・いつまで） |

## デモ前チェックリスト

- [ ] 顧客データ or 顧客に近いデータで事前リハ済み
- [ ] 詰まった時のフォールバック（スクショ/録画）を用意済み
- [ ] `00_data_policy.md` の説明用一文を頭に入れた
- [ ] 「今日決めてほしいこと」を1つに絞った

## デモ後

結果を `pm_brain/cases/` の該当案件ファイルの「顧客フィードバック」に即日転記し、`calibration_log.md` に1行追加する。
