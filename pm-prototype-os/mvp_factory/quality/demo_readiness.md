# Demo Readiness

顧客デモの品質は、コード品質だけでなく「失敗しても検証を継続できるか」で決まる。

## 3モード

### Live

実データ・実処理で動かす。価値検証の中心。

### Replay

事前に成功した入力・処理結果を再生する。外部API・AI・ネットワーク障害時の代替。

### Mock

完全固定データで画面・業務フローを見せる。入力データが未準備でもUI仮説を検証する。

## 必須チェック

- [ ] デモ開始時の初期データが固定されている
- [ ] reset手順が1コマンドまたは1操作
- [ ] 外部API失敗時にReplayへ切り替えられる
- [ ] AI出力失敗時に前回成功結果を表示できる
- [ ] 「処理中」「失敗」「判定不能」が区別される
- [ ] 顧客の原本と出力根拠を並べて確認できる
- [ ] デモ終了時に顧客判断を記録する

## 禁止

- デモ本番で初めて依存関係をインストールする
- 1つのネットワーク経路だけに依存する
- AIが必ず正答する前提で進行する
- 失敗を隠して成功画面だけ見せる
- 顧客の質問をその場の口頭回答で終わらせる
