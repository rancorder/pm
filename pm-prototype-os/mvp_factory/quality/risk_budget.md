# MVP Risk Budget

MVPではすべてを高品質にしない。**捨ててよい品質と、絶対に捨てない品質**を先に決める。

## 原則

```text
見た目・大量対応・完全自動化は捨てられる
データ破壊・機密漏えい・根拠なし断定・顧客デモ停止は捨てない
```

## 標準リスク予算

| 項目 | MVPでの標準判断 | 理由 |
|---|---|---|
| 高度なデザイン | 捨てる | 仮説検証に直接効かない |
| 大量データ対応 | 条件付きで捨てる | 検証量を明示すればよい |
| ログイン・権限 | デモ限定なら捨てる | 本番境界を明記する |
| 完全自動化 | 捨てる | HITLで価値を先に検証する |
| 例外処理網羅 | 捨てる | 顧客クリティカルケースだけ残す |
| データ破壊 | 許容しない | 復旧不能リスク |
| 機密漏えい | 許容しない | 契約・信用リスク |
| 根拠なしAI回答 | 許容しない | 業務判断を誤らせる |
| 判定不能時の推測 | 許容しない | abstentionを品質として扱う |
| デモ全停止 | 原則許容しない | Replay/Mockで回避する |
| 判断根拠の欠落 | 許容しない | 再現・レビューできない |

## 案件ごとの上書き

標準判断を変える場合、MVP Contractへ次を記録する。

- 何を許容するか
- なぜ許容するか
- 顧客へ説明したか
- いつまでに解消するか
- 本番化を止める条件は何か
